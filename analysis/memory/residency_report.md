  ANSWER: no -- eviction's advantage is real, not an artifact of the
  baseline's re-reads.  evict-1024 at batch 32 holds ~16x from a 0 KB
  buffer to a 128 MB one; at batch 1 it slips only 2.460x -> 2.295x.
  The reason is scale: the dense K+V working set is 32 MB per layer at
  batch 1 and 1,024 MB at batch 32, so no plausible on-chip buffer holds
  a meaningful fraction of it.  Residency cannot rescue a cache that was
  never going to fit.

  The two are complementary rather than competing.  Eviction shrinks the
  working set to a size a buffer can actually hold -- which is exactly
  the Stage 1b capacity result -- and residency then removes what is left
  of the traffic.  The order matters: shrink first, then keep resident.
