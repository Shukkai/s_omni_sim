# Select-without-evict

*What page selection actually costs, once granularity is charged*

Generated by `analysis/memory/selective_run.py` — re-run it to refresh.
Model: LLaMA-3-8B on Omni-LUT, 4-bit KV, context 32,768, 64 B DRAM burst.
Dense decode baseline: 25,837,658,112 B DRAM read, TPOT 128.808 ms.

## Key findings

- **Selection and compacted eviction are byte-identical** at equal retained entries, at every `k` tested — so the flat-bandwidth model was right, and `kv_budget.py`'s decision to defer this study was correct for this hardware.
- The reason: a 4-bit KV entry is `128 x 4/8` = **64 B, exactly one DDR-class burst**, so a page-gathering reader is burst-aligned at every page size — down to a single token.
- **Granularity is a bit-width property here, not a selection property.** At 3-bit KV an entry is 48 B and a single-entry gather does pay 1.33x.
- What selection actually costs is **metadata**, which scales with the context rather than with what was selected — so its share grows as selection gets more aggressive.

## A. Selection vs compacted eviction, at equal retained entries

Page 16, 4-bit KV. If burst granularity separated the two, it would show here.

| pages read | entries | eviction (eff) | selection (eff) | ratio |
|---:|---:|---:|---:|---:|
| 16 | 256 | 17,913,118,720 | 17,913,118,720 | 1.000x |
| 64 | 1,024 | 18,100,289,536 | 18,100,289,536 | 1.000x |
| 256 | 4,096 | 18,848,972,800 | 18,848,972,800 | 1.000x |
| 1,024 | 16,384 | 21,843,705,856 | 21,843,705,856 | 1.000x |

> Identical. A page of 16 entries is 1,024 B — a whole number of 64 B bursts — so every page boundary is already burst-aligned and gathering costs nothing extra.

## B. Where granularity *does* bite

Entry width is `head_dim 128 x kv_bits / 8`, against a 64 B burst.

| kv_bits | entry | page | run | charged | waste |
|---:|---:|---:|---:|---:|---:|
| 4 | 64 B | 1 | 64 B | 64 B | 1.00x |
| 4 | 64 B | 4 | 256 B | 256 B | 1.00x |
| 4 | 64 B | 16 | 1024 B | 1024 B | 1.00x |
| 3 | 48 B | 1 | 48 B | 64 B | 1.33x |
| 3 | 48 B | 4 | 192 B | 192 B | 1.00x |
| 3 | 48 B | 16 | 768 B | 768 B | 1.00x |

> 4-bit KV is burst-aligned at **every** page size, including page = 1 (token-granular, TidalDecode-style). 3-bit KV is 48 B per entry and is not: a single-entry gather pays 1.33x.

## C. What selection metadata costs

Quest-style per-page min/max, read once per page per token over the **full** context — not over what was selected.

| page | read | no metadata | with metadata | overhead | TPOT |
|---:|---:|---:|---:|---:|---:|
| 16 | 50% | 21,847,605,248 | 22,317,563,904 | 1.022x | 90.692 ms |
| 16 | 25% | 19,851,116,544 | 20,321,075,200 | 1.024x | 70.966 ms |
| 16 | 10% | 18,650,103,808 | 19,120,062,464 | 1.025x | 59.099 ms |
| 16 | 3% | 18,092,490,752 | 18,562,449,408 | 1.026x | 53.590 ms |
| 64 | 50% | 21,859,303,424 | 21,976,940,544 | 1.005x | 89.825 ms |
| 64 | 25% | 19,862,814,720 | 19,980,451,840 | 1.006x | 70.098 ms |
| 64 | 10% | 18,661,801,984 | 18,779,439,104 | 1.006x | 58.232 ms |
| 64 | 3% | 18,100,289,536 | 18,217,926,656 | 1.006x | 52.684 ms |

> Metadata scales with the **context**, not with what was selected, so its share grows as selection gets more aggressive — a floor under how far selection can pay. A larger page amortises it directly.

## D. How much of the paper speedup survives

Page 16, 4-bit KV. Decode TPOT speedup vs dense.

| read | flat model | + burst granularity | + metadata |
|---:|---:|---:|---:|
| 50% | 1.441x | 1.441x | 1.420x |
| 25% | 1.849x | 1.849x | 1.815x |
| 10% | 2.229x | 2.229x | 2.180x |
| 3% | 2.464x | 2.464x | 2.404x |

> Burst granularity costs selection **nothing** at 4-bit KV. Metadata is what bends the curve, and it bends it hardest exactly where the paper numbers look best.
