# Attention score staging: the biggest DRAM term was an assumption

Generated by `analysis/memory/prefill_run.py`.
Model: LLaMA-3-8B on Omni-LUT, 4-bit KV, FP16 activations.

```
Pre-flight: 7 assertions passed

A. Prefill DRAM before and after staging  (batch 1)

   context   row buf |         spilling         staged   staged+KV read  reduction
      2048      5 KB |   19,797,114,880  2,617,245,696    2,684,354,560       7.4x
      8192     17 KB |  277,696,479,232  2,818,572,288    3,087,007,744      90.0x
     32768     65 KB | 4,401,670,389,760  3,623,878,656    4,697,620,480     937.0x

  'staged' alone is the documented NON-configuration: scores stay on
  chip but prefill still reads no K/V, so it under-reads.  The usable
  column is the third.

  The buffer is one query row's score vector for ONE (batch, head)
  instance, sized for the LONGEST row the run produces -- context plus
  output tokens, since decode grows kv_len.  Size it for prefill alone
  and the scores silently spill again as soon as decoding starts.

B. Does the corrected standard path agree with FlashAttention?

   context |         standard   flash(block=seq)   flash(block=256)  256 penalty
      2048 |    2,684,354,560      2,684,354,560      3,154,116,608         1.2x
      8192 |    3,087,007,744      3,087,007,744     11,408,506,880         3.7x
     32768 |    4,697,620,480      4,697,620,480    141,062,832,128        30.0x

  Exact agreement at one Q block is the check that the correction is
  right: both paths then reduce to Q/K/V read once plus KV writeback.
  The block=256 penalty is flash's real tiling cost -- K/V re-read once
  per Q block -- and is why a larger block is cheaper.

C. What it does to TTFT  (batch 1)

  No published number moves: no tracked markdown contains a TTFT or a
  prefill DRAM figure, and every study that emits TTFT runs on the flash

  Isolated by differencing, the score spill is 11.1% of decode ATTENTION

  also carries the V-cache read.

  study2.md sections 7-9 were produced with the spill on, so section 7's
  'KV share of decode DRAM' is really ATTENTION share and is ~11% scores.
  The TPOT shift is 1.005x-1.016x, so those sections need correcting
```
